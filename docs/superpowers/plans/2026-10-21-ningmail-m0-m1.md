# NingMail M0+M1 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 从空仓库构建一个可在麒麟 V10 上安装运行的 NingMail MVP：三栏界面、账号配置、IMAP 收信、SMTP 发信、SQLite 本地缓存、HTML 阅读和纯文本写信。

**架构：** Qt 6.8 + QML 前端，C++20 核心；单进程多线程；libetpan 负责 IMAP/SMTP；litehtml 负责 HTML 渲染；SQLite 负责本地存储。M1 只实现同步最近 500 封头部，IDLE/增量同步/全文搜索/日历通讯录留到后续计划。

**技术栈：** Qt 6.8 LTS、C++20、CMake 3.21+、Ninja、libetpan、litehtml、Gumbo、SQLite、ICU、OpenSSL、libsecret、Catch2、Qt Test。

**规格：** `docs/superpowers/specs/2026-10-21-ningmail-design.md`

---

## 全局约束

- 目标平台：麒麟 V10 SP1 2303+/SP3，ARM64（飞腾/鲲鹏）与 x86_64（兆芯/海光）；glibc 2.31 基线。
- 不使用 QtWebEngine、Chromium、WebKit；HTML 渲染只走 litehtml。
- C++20；命名空间 `ningmail`；产品名 `NingMail`；可执行文件 `ningmail`。
- 网络、MIME 解析、HTML 渲染不得在 GUI 线程执行；M1 的数据库写入是例外，但必须批量、单事务、可测量（≤500 封/次，目标 <200ms），M2 迁移到独立存储线程。
- SQLite 使用 WAL、`foreign_keys=ON`、`busy_timeout=5000`；所有写操作串行。
- 邮件 HTML 不执行 JavaScript，默认屏蔽远程图片；所有链接用外部浏览器打开。
- 所有 UI 文案用 `qsTr()` 包裹；M1 源字符串直接用中文。
- 每个任务先写失败测试，再实现，再跑测试，最后 commit；提交信息用 Conventional Commits。
- 构建目录 `build/`；格式检查 `clang-format --dry-run --Werror`；静态检查 `clang-tidy`（CI 中 warn，不阻断 M1）。
- 单元测试命令：`ctest --test-dir build --output-on-failure`；Catch2 可执行文件 `build/tests/unit/ningmail_tests`。
- 第三方代码放在 `third_party/` 或 `libs/render/litehtml_qt/`，保留上游许可证头。
- 分层：`libs/mail`、`libs/render` 只能包含 `app/core` 的 header-only 类型（`Types.h`、`MailError.h`、`MailBackend.h`），不得包含或链接 `app/core` 的存储/UI 实现；依赖方向为 `app → libs → app/core 头文件`，不得反向。

## 审查重点（Review Focus）

1. **Malformed MIME / 未知字符集**：截断的 multipart、缺失 boundary、GB18030/GBK 正文、坏 RFC 2047 头部，必须返回 `MailError` 或降级为可读文本，不能崩溃或死循环。对应测试在任务 6。
2. **恶意 HTML / 远程内容**：`<script>`、`<iframe>`、`onclick`、`javascript:`、远程 `<img>` 必须被移除或阻断；渲染器不得发起网络请求。对应测试在任务 10a/10b。
3. **重复同步 / UIDVALIDITY 变化**：同一 UID 重复插入不能产生重复行；UIDVALIDITY 变化时清空该文件夹并重建，草稿/发件箱不受影响。对应测试在任务 7/8/13。
4. **GUI 阻塞**：同步、MIME 解析、HTML 渲染不得卡住 UI；500 封批量写入 <200ms；大 HTML 渲染有高度/耗时上限。对应测试在任务 7/8/9a/10b。
5. **超大邮箱/超大邮件**：1 万封列表分页不能一次性加载；单封 HTML 超过 1MB 或高度超过 20000px 时必须降级，不能 OOM。对应测试在任务 7/9a/10b。

## M1 范围与限制

M1 交付：应用骨架、账号配置、IMAP 收信（最近 500 封）、SMTP 发信、本地缓存、三栏列表/阅读、纯文本写信、HTML 基础渲染、deb 打包。

M1 明确不做（后续计划）：
- IDLE、增量同步、离线队列、FTS5 搜索（M2）。
- litehtml 分块/文本选择/远程图片白名单 UI（M2）。
- 托盘、通知、日历、通讯录（M2/M3）。
- Exchange、OAuth2、S/MIME、国密（V1.1）。
- 发件箱重试/5 秒撤销（M2；M1 只做一次发送 + 失败提示）。

- [ ] **步骤 4：实现 MIME 解析器**

- 头部：按首个空行分离；折行（CRLF + 空格/Tab）合并；按第一个 `:` 分割；字段名小写。
- `decodeHeader`：处理 RFC 2047 `=?charset?B?...?=` 和 `=?charset?Q?...?=`；相邻编码词之间的空白按 RFC 2047 丢弃；非编码文本原样保留。

- 地址：按逗号分割（忽略引号和尖括号内的逗号）；支持 `"Name" <a@b>`、`a@b`、`Name <a@b>`。
- 日期：`QDateTime::fromString(value, Qt::RFC2822Date)`；失败用 `QDateTime::currentDateTimeUtc()`。
- 附件文件名：`Content-Disposition: filename` / `filename*=`（RFC 2231）解码；`Content-ID` 去尖括号。
- 纯文本邮件：`html` 为空，`plainText` 为解码后的正文。
- 任何未捕获异常/越界都转成 `MailError{Protocol}`。

## 计划自检

- **规格覆盖（M0/M1）**：目标平台、Qt/QML 架构、SQLite 数据模型、IMAP 头部同步、正文按需拉取、SMTP 发送、三栏 UI、litehtml 阅读、HTML 安全、deb 打包均有任务。FTS/IDLE/日历/通讯录/Exchange 明确留给后续计划。
- **类型一致性**：`Account`、`Folder`、`MessageHeader`、`MessageBody`、`MailFlags`、`MailError`、`Result<T>`、`AttachmentMeta` 由任务 2 定义（header-only）；`MailBackend`/`OutgoingMessage` 由任务 5 定义；`Draft`/`OutboxItem` 只在任务 11/12 定义；后续任务只引用，不重复定义。`AppController` 的最终方法集合 = 任务 9b（initialize/selectFolder/refresh/openMessage/composeNew/reader）+ 任务 11（setDraftStore/saveDraft/sendMessage）+ 任务 12（setSendService）+ 任务 15（createAccount/openComposer），构造参数只在任务 9b 定义一次。
- **分层**：`libs/mail`、`libs/render` 只包含 `app/core` 的 header-only 类型；CMake 目标 `ningmail_mail`、`ningmail_render` 不链接 `ningmail_core`；`ningmail_ui` 是 QML 模块库，由 `app` 可执行文件链接。
- **测试覆盖**：每个产品任务都有失败测试/命令/通过标准；M0 是 spike，用结果文档而非 TDD。
- **审查重点对应**：MIME→任务 6；HTML/远程内容→任务 10a/10b（含 1MB 降级）；重复同步/UIDVALIDITY→任务 7/8/13；GUI 阻塞→任务 7/8/9a/10b（渲染在后台线程）；超大邮箱→任务 7/9a（1 万分页测试）。
- **已知取舍**：M1 同步只在刷新时拉最近 500 封；M1 数据库写入在 GUI 线程批量执行（≤500/事务，<200ms），M2 迁移到存储线程；M1 不做文本选择/远程图片 UI/托盘/通知；写信按钮在任务 11 前禁用是刻意状态。

## 执行交接

计划已保存到 `docs/superpowers/plans/2026-10-21-ningmail-m0-m1.md`。请审阅；确认后选择执行方式：

- **子代理驱动**：每个任务由全新子代理实现，再由全新审查者检查；适合这份任务多、接口依赖强的计划。
